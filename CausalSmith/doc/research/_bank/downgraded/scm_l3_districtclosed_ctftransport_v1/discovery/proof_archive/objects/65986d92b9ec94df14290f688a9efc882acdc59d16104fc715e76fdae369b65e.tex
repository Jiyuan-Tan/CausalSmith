By definition, \(\mathfrak I_{\mathrm{CTFTR}}\) retains only observational and atomic hard-interventional constructors that are also constructors of the DCTFTR typed-menu grammar. Sending the graph, each domain label, descriptor, supplied law, and query to the identically labelled DCTFTR object is therefore injective and type preserving. The conditional and stochastic-policy constructors excluded from this restricted carrier are not mapped.

Likewise, \(\mathfrak I_{\mathrm{CTFIDU+}}\) is the one-domain intersection for which a constructor map into the DCTFTR partial-copy syntax is explicitly declared. Set \(\mathcal S=\{\star\}\), send each action through that declared map, and retain the graph, supplied cells, and target. This is injective and type preserving. No action lacking the constructor map is used.

On either image, \(\mathrm{thm:recursion\text{-}soundness}\) proves that every successful DCTFTR expression equals the causal query in every compatible model. The already established nodes \(\mathrm{lem:ctftr\text{-}published\text{-}soundness}\) and \(\mathrm{lem:ctfiduplus\text{-}published\text{-}soundness}\) give the same semantic equality for a successful published expression on the corresponding input restriction. Thus successful expressions agree with the same query; no equality of syntax or traces is needed.

Both embeddings are proper. In \(\mathfrak I_{\mathrm{bin}}\),
\[
p=P^s(Y_0=1,Y_1=1)=\frac38
\]
is a joint cross-world cell, not an observational or atomic hard-interventional descriptor, so the first restricted carrier does not contain the instance. For the second carrier, a one-SCM instance has one factual law for \(Z\), whereas the binary family requires simultaneously
\[
P^\star(Z=1)=0,
\qquad
P^s(Z=1)=1.
\]
No single probability law satisfies both equations. The two-domain DCTFTR family permits the difference because \(Z\in\Delta_s\). Hence the binary instance lies in \(\mathfrak I_{\mathrm{DCTFTR}}\) but outside each embedded restriction.
